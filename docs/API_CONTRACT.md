# Local API contract

Base URL: `http://127.0.0.1:8000`. The Vite development server proxies `/api` from port 5173. No API keys or role authentication are implemented. Only local Host values and the explicitly configured local browser Origins are accepted; this is not a production security boundary. Automatic OpenAPI/docs endpoints are disabled.

| Method and path | Request | Response |
|---|---|---|
| GET /api/health | None | 200 `{status:"OK",synthetic:true,message}` when three labs and an active public key exist; otherwise 503 with status ERROR |
| POST /api/verify | Multipart: exactly `file`, `manifest`, `signature` | 200 committed VerificationResult, including quarantined decisions |
| GET /api/verifications | Optional status ACCEPTED/QUARANTINED; limit 1–100, default 50 | Result array, newest first |
| GET /api/verifications/{verification_id} | Record ID | Result; 404 if absent |
| GET /api/audit | Optional verification_id; limit 1–200, default 100 | Audit event array, newest event first |
| GET /api/laboratories | None | Three laboratory records |

## Submission

Use multipart/form-data generated by the HTTP client. Only `file` has a filename. `manifest` is the exact UTF-8 canonical JSON text described in MANIFEST_V1.md; `signature` is its detached base64 Ed25519 signature. No uploaded public key is accepted.

Limits: file 2,097,152 bytes; manifest 8,192 bytes; signature 88 ASCII bytes; entire multipart request 3,145,728 bytes; three parts; bounded headers and boundary. Actual streamed bytes are counted independently of Content-Length. Duplicate fields, incomplete multipart, duplicate JSON keys, invalid UTF-8, nonfinite JSON and invalid signature encodings are rejected. Empty/inconsistent file packages cannot be accepted.

## VerificationResult

Exact field types are defined by `backend/app/schemas.py` and validated on response:

```text
verification_id, received_at: string
status: ACCEPTED | QUARANTINED
reason_code: VALID | INVALID_METADATA | UNKNOWN_OR_REVOKED_KEY |
             SENDER_KEY_MISMATCH | INVALID_SIGNATURE | HASH_MISMATCH | SIZE_MISMATCH
details: safe human-readable string
claimed_laboratory_id, claimed_key_id: string | null
verified_laboratory_id, verified_key_id: string | null
metadata_authenticated: boolean
file_name: string | null
file_size_bytes: integer
computed_sha256: lowercase hexadecimal SHA-256
manifest: validated Manifest V1 | null
checks: [{name, status: PASS | FAIL | SKIPPED}]
```

Check order: metadata, trusted_key, sender, signature, file_name, size, sha256. A failure skips subsequent checks. Claimed identities are untrusted until signature verification succeeds. A valid signature can authenticate metadata while the file itself is quarantined for a size or digest mismatch. No ACCEPTED response is returned before submission, decision and nine lifecycle audit events commit in one transaction.

AuditEvent: event_id integer, verification_id nullable string, created_at UTC string, actor_laboratory_id string, event_type string, details string. Laboratory: laboratory_id, name, sector, role, all strings.

## Errors

Malformed transport/JSON/base64 and invalid queries: 400. Payload limits: 413. Foreign browser Origin: 403. Unknown resource: 404. Unsupported method: 405. Storage unavailable: 503. Unexpected operational failure: safe 500. None becomes ACCEPTED.

Except readiness's documented response, errors use:

```json
{"error":{"code":"BAD_REQUEST","message":"Safe description","request_id":"uuid","audit_recorded":true}}
```

Possible codes also include TOO_LARGE, FORBIDDEN, NOT_FOUND, UNAVAILABLE and INTERNAL_ERROR. Transport rejection attempts a separate bounded audit entry. Query/Host/Origin failures are not promised an audit entry. Storage failure may prevent auditing; `audit_recorded` describes that fact. Responses set no-store, nosniff and a request ID. Raw exception text, private keys and file content are not returned.
